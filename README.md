# 微信数据监听（微信群消息自动采集）

一个运行在 Windows 上的自动化小工具：监听指定的微信群，识别其中的「业务办理」消息，解析成结构化记录后自动写入飞书电子表格；同时反向轮询表格，把已办理完成的记录自动 @ 回原群的需求人。

目标是替代「人工盯群 → 手动抄录到表格 → 再手动回复群」这条重复链路。

---

## 功能概览

1. **群消息采集**：定时扫描微信 PC 客户端的会话列表，只进入有未读角标的监控群（以及当前正打开的监控群），避免无效切群。
2. **业务消息筛选**：只处理文本／引用回复，且消息必须同时提到配置的机器人／客服昵称（`wechat.bot_aliases`）并包含业务关键字（`wechat.keywords`）。
3. **结构化解析**：按 `学员编号 / 姓名 / 编号 / 订单号 / 业务办理 / 备注` 字段区间截取，字段空缺也不会串行。
4. **写入飞书表格**：批量写入 A–H 列，自动定位第一个整行为空的空行，避免覆盖已有数据。
5. **自动群内回复**：每抓取 5 轮后执行一次回复检查 —— 找出「是否办理完成 = 是」且「是否群内回复 ≠ 是」的记录，回到对应群 `@需求人` 发送办理情况（支持文字 + 多张图片）。
6. **回写状态**：发送成功后把「是否群内回复」置为「是」；发送前会重新定位行号，防止表格变动导致回错行。
7. **消息去重**：基于内容 MD5 记录已处理消息，状态文件只保留最近 5000 条。
8. **单实例锁**：避免两个实例同时操作微信、同时写入表格。
9. **图形化控制面板**：`launcher.py` 提供开始/停止按钮和彩色运行日志。

## 目录结构

```
客服数据监听/
├── main.py                  # 主程序：主循环、回复检查、单实例锁、日志初始化
├── launcher.py              # Tkinter 控制面板（开始/停止 + 实时日志）
├── wechat_uia.py            # 微信侧：基于 wxauto4 的群扫描、翻页读消息、@发送
├── feishu_api.py            # 飞书侧：Sheets API 读写、图片下载、待回复记录定位
├── msg_parser.py            # 消息解析：从群消息文本提取业务字段
├── config.yaml.example      # 配置模板（复制为 config.yaml 后填写自己的信息）
├── requirements.txt         # Python 依赖
├── setup.bat                # 一键安装依赖并检查配置
└── 启动程序.bat              # 一键启动控制面板（用 pythonw，不弹黑窗）
```

| 文件 / 目录 | 说明 |
| --- | --- |
| `config.yaml` | 真实配置，含飞书密钥 |
| `monitor.log`（含 `.1/.2/.3`） | 运行日志，20MB 轮转，最多保留 3 个备份 |
| `processed_state.json` | 消息去重状态 |
| `monitor.lock` | 单实例锁 |

| `wxauto4离线安装包.zip` | 第三方离线安装包，仅在无网络环境部署时使用，不随仓库分发 |

## 表格列约定

程序读取 A–M 列，写新记录时只写 A–H 列：

| 列 | 字段 | 来源 |
| --- | --- | --- |
| A | 学员编号 | 群消息解析 |
| B | 姓名 | 群消息解析 |
| C | 班级编号 | 群消息解析 |
| D | 订单号 | 群消息解析 |
| E | 业务办理 | 群消息解析 |
| F | 备注 | 群消息解析 |
| G | 群聊 | 消息所在群名 |
| H | 需求人（发送人） | 消息发送者 |
| I | 办理人 | 人工填写 |
| J | 是否办理完成 | 人工填写，值为「是」时进入回复队列 |
| K | 办理情况 | 人工填写，支持文字和图片 |
| L | 办理情况2 | 同上，与 K 列内容合并发送 |
| M | 是否群内回复 | 程序回写「是」 |

> 第 1 行为表头，数据从第 2 行开始。

## 环境要求

- **操作系统**：Windows 10 / 11
- **Python**：3.10 及以上
- **微信**：Windows 版微信 PC 客户端，且需保持登录、窗口不能被关闭
- **飞书**：企业自建应用 + 一个电子表格

依赖（见 `requirements.txt`）：

| 包 | 用途 |
| --- | --- |
| `wxauto4` | 通过 UI Automation 操作微信客户端 |
| `requests` | 调用飞书开放接口 |
| `PyYAML` | 读取 `config.yaml` |
| `pywin32` | 窗口操作、`WScript.Shell` 翻页按键 |
| `psutil` | 单实例锁的进程存活判断 |

## 快速开始

### 1. 安装依赖

双击 `setup.bat`，或手动执行：

```bat
pip install -r requirements.txt
```

### 2. 创建飞书应用

1. 打开 [飞书开放平台](https://open.feishu.cn/) → 开发者后台 → 创建**企业自建应用**。
2. 在「凭证与基础信息」中拿到 `app_id` 和 `app_secret`。
3. 在「权限管理」中开通电子表格与云文档相关权限（至少需要读取、写入电子表格，以及下载素材/图片）。
4. 发布应用版本并等待管理员审核通过。
5. 打开目标电子表格，把该应用添加为**协作者**（可编辑），否则接口会返回无权限。
6. 从表格链接中取出 `spreadsheet_token`：
   `https://xxx.feishu.cn/sheets/`**`<spreadsheet_token>`**`?sheet=<sheet_id>`

### 3. 写配置

```bat
copy config.yaml.example config.yaml
```

然后编辑 `config.yaml`，填入飞书凭证、表格 token 和要监听的群名。

配置项说明：

| 配置项 | 说明 |
| --- | --- |
| `feishu.app_id` / `feishu.app_secret` | 飞书自建应用凭证 |
| `feishu.spreadsheet_token` | 电子表格 token |
| `feishu.sheet_id` | 工作表 ID，可留空（留空时用第一个工作表） |
| `wechat.groups` | 要监听的群名列表 |
| `wechat.bot_aliases` | 消息中必须提到的机器人／客服昵称，任一命中即通过；不要求带 @ 符号 |
| `wechat.keywords` | 消息还必须包含的业务关键字，任一命中即通过 |
| `wechat.check_interval` | 轮询间隔（秒） |
| `logging.level` / `logging.file` | 日志级别与日志文件 |

### 4. 运行

```bat
python launcher.py        :: 图形化控制面板（推荐）
python main.py            :: 命令行直接运行，Ctrl+C 停止
```

首次启动会打印飞书连接测试结果，并提示微信是否已登录。建议先保持 `logging.level: DEBUG`，观察日志确认筛选与解析符合预期后再改回 `INFO`。

## 工作原理

```
微信客户端 ──(wxauto4 / UIA)──► wechat_uia.py
                                    │ 未读群扫描 + 翻页读消息 + 关键字筛选
                                    ▼
                               msg_parser.py  字段区间截取
                                    ▼
                               feishu_api.py  A–H 列写入飞书表格

飞书表格 ──(每 5 轮抓取后)──► 找出「办理完成=是 且 未群内回复」
                                    │ 重新定位行号 → 下载 K/L 列图片
                                    ▼
                               wechat_uia.py  @需求人 发送文字+图片
                                    ▼
                               回写 M 列 = 是
```

几个刻意的设计取舍：

- **抓取与回复在同一个线程内交替执行**，不并行，避免两条流程同时操作微信界面导致切群冲突。
- **筛选词与群名全部外置到 `config.yaml`**，源码里不出现任何真实昵称、群名和组织标识，方便开源或分享。
- **进入群聊后一定要校验当前会话名**，因为微信会话列表会随新消息重排，直接点击可能点开别的群，把 A 群的消息记到 B 群头上。
- **翻页采用「锚点验证 + PageDown 填缝」**，而不是盲目 PageUp，减少漏读。
- **发送前重新定位行号**，因为快照行号在表格变动后会漂移。
- **同一学员同群同编号存在多行待回复时**，用业务字段内容指纹消歧；仍无法区分则跳过并告警，宁可不做也不错做。

## 常见问题

**飞书连接失败**

依次检查：`app_id` / `app_secret` 是否正确；电子表格是否已把应用添加为协作者；应用版本是否已发布并通过审核；本机能否访问 `open.feishu.cn`。

**提示「未检测到微信PC客户端」**

程序不会退出，会持续等待。请确认微信已登录，且窗口标题是「微信」。程序会把微信窗口调整为屏幕高的 2/3 宽并移到左上角，这是为了方便读取消息列表，属于预期行为。

**群消息一直采不到**

1. 群名要和微信里显示的一致（代码做了去掉 emoji 的模糊匹配，但不做错别字容错）。
2. 消息里必须提到 `wechat.bot_aliases` 中配置的昵称，并且包含 `wechat.keywords` 中的业务关键字。
3. 消息里至少要能识别到 `学员编号` 或 `姓名` 字段（中英文冒号都支持）。

**群内回复一直不发**

需要 J 列「是否办理完成」为「是」、M 列「是否群内回复」不是「是」，且 G 列群聊、H 列需求人非空。把日志级别调成 `DEBUG`，可以看到每条记录的判定细节。

**重复启动**

第二个实例检测到 `monitor.lock` 里的进程仍然存活时会直接退出。若程序被强制结束后残留了锁文件，下次启动会自动接管。

## 注意事项

- 本工具通过 UI 自动化直接操作微信客户端，**运行期间请勿手动抢占鼠标键盘**，也不要手动切换会话，否则可能采集错群或发错群。
- 自动回复是真实发送的行为，调试时建议先用测试群验证。
